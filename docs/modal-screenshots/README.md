# Modal dialogs: what each one is, and where they diverge from platform convention

Every dialog this application opens, photographed and described. The PNGs beside
this file are regenerated by `tools/modal-shots/capture_modals.sh`; each is
cropped to the dialog's own rect with 28 px of surrounding window, so the crop
follows the dialog when its content changes rather than slicing a fixed box out
of the middle of the screen.

**This document was written twice.** §2–§5 are the evaluation as first made,
against `3002d73`: thirty-four dialogs, ten findings, a nine-item standard. §0
is what happened next -- the standard was built as `ui/Dialog` and every dialog
was moved onto it -- and says, finding by finding, what closed and how. The
images beside this file are the dialogs **as they are now**; the originals the
findings were made against are in [`before/`](before/), and every inventory row
links both. The inventory's `Size` and `Commit` columns are the current values;
§4's tables keep the old ones, because those are the measurements the findings
rest on.

Captured in a 2560 × 1580 framebuffer (1280 × 790 points at 2×). **All sizes
below are framebuffer pixels**, straight off ImGui's own `OpenPopupStack`, not
measured off the images.

## 1. How the captures are made

Two flags were added for this, both in `src/main.cpp`:

- **`--open-modal <MenuActionName>`** enqueues one menu action on the first
  frame, through the same `enqueueMenuAction()` queue the native macOS menu bar
  uses. Every dialog here is opened by exactly one `MenuAction`, so this is one
  flag rather than thirty; the names are `menuActionName()`'s, resolved at parse
  time so a typo fails before a window opens.
- **`--screenshot` now prints the open modal's rect** —
  `[screenshot] modal "<title>" rect x y w h` — read off
  `ImGuiContext::OpenPopupStack`.
- **`--press-key <Escape|Return> [frame]`** (added with §0) queues one key
  press through `io.AddKeyEvent()`, the same queue the SDL backend feeds, on
  the given frame (default 10) and releases it on the next. With `--open-modal`
  and `--screenshot` this is how S1 is shown rather than claimed: a dialog plus
  Escape must photograph no dialog.

The rect is reported rather than guessed because every dialog here is
`ImGuiWindowFlags_AlwaysAutoResize`: its size is a function of its content and
its position is a function of its size. A hardcoded crop box would start
cutting dialogs in half the first time a label got a word longer — which is
exactly the kind of change this document exists to notice. Cropping by diffing
against a no-dialog baseline was the other candidate and cannot work here:
seven of these dialogs live-preview into the canvas, so the region that differs
from a plain launch is the whole window.

```bash
tools/modal-shots/capture_modals.sh
```

This is **not** a regression harness — `tools/golden/run_golden.sh` is that, and
it diffs against blessed references. This script diffs nothing; it is a contact
sheet for a human, regenerated on demand.

## 3. What could not be captured

The application has thirty-seven modal ids; §2 covers thirty-five of them.
Here is the remainder, each with the reason, because "absent from the contact
sheet" and "does not exist" must not look the same.

- **View > Add Guide…** — *was* here, and is now
  [add-guide.png](add-guide.png) in §2.6. As first evaluated it was the only
  non-modal `BeginPopup` in the application, and ImGui closes a non-modal popup
  the moment anything else takes focus (`FocusWindow()` →
  `ClosePopupsOverWindow()`), so under `--open-modal AddGuide` it did not
  survive to a captured frame at 2, 5, 30 or 90 settle frames. S9 made it a
  modal, and the first capture after that photographed it at 90 frames like
  every sibling -- which also settles the question this entry used to leave
  open: the popup was closing on focus, not on anything a menu click would do
  differently.
- **Close document** (`kCloseDecisionPopup`) — the Save / Don't Save / Cancel
  question, raised only when the document being closed is dirty. `MenuAction::
  CloseDocument` on a clean `--demo-document` closes it instead of asking, and
  no launch flag makes a document dirty. It is also the **best-behaved dialog
  in the application** — see §4.1.
- **The file-path problem prompt** (`kDocPathProblemPopup`) — "Could not
  open/save that file", with `Choose Another File…`. Reachable only after the
  OS panel returns a path that the open or save then fails on.
Two *states* are also under-covered, though their dialogs are in §2:
**Export As** and **Export Comps** are both photographed with no output path,
which is what a launch can produce; their populated and mid-error states are
not.

## 4. Evaluation against desktop convention

Ten divergences, ordered by how much they cost a user. Every one is visible in
the images above; the counts come from the source.

### 4.1 No keyboard dismissal, and no close button — 33 of 34

> **Closed.** Escape cancels and Return commits in all thirty-five, through one footer, and the pair is photographed rather than asserted (§0, S1). The close box stays absent by design.

This build never sets `ImGuiConfigFlags_NavEnableKeyboard`, and ImGui's Escape
handling is gated on exactly that flag (`NavUpdateCancelRequest()`,
imgui.cpp:15176). Every `BeginPopupModal` here is called with `p_open ==
nullptr`, which suppresses the title-bar close box, and none passes
`ImGuiWindowFlags_NoResize`-adjacent flags that would add one back.

The result: **the in-body Cancel button is the only way out of 33 of these 34
dialogs.** Escape does nothing. Return does nothing. There is no ⌘. and no title
bar ✕.

The exceptions prove it was noticed and then not generalised:

- **Close document** reads Escape and Return itself, through
  `app/CloseDecision`'s asserted key mapping, and its own source comment states
  the reason — "this build does not set `ImGuiConfigFlags_NavEnableKeyboard`, so
  ImGui neither activates a focused button on Enter nor closes a modal on
  Escape; both keys are ours to read."
- **Layer Properties** reads Escape (`ui/MacPaintUI.cpp:3769`).

Nothing else does. This is the single largest gap, and the cheapest to close.

### 4.2 The commit button has nine different labels, and sits on the wrong side

> **Closed.** Right-aligned Cancel-then-commit everywhere, the commit drawn as the default; `Apply` for the twenty-one previewing dialogs and a verb for the rest (§0, S2–S3).

Reading down §2's Commit column: `Create`, `Discard and revert`, `Export`,
`Resize`, `Apply`, `Blur`, `Sharpen`, `Add Noise`, `Emboss`, `Despeckle`,
`Motion Blur`, `Levels`, `Curves`, `Exposure`, `Mix`, `Grow`, `Shrink`,
`Feather`, `Select`, `Recover`.

Within the thirteen adjustments alone — dialogs that share one button
function — four are named after their own dialog (`Levels`, `Curves`,
`Exposure`), one is a verb nobody uses (`Mix`), and eight are `Apply`. A user
cannot learn "the button on the left commits" because the button on the left is
never called the same thing twice.

And it is on the left. macOS puts the default button in the **trailing** (right)
position, Cancel to its left; Windows puts OK-then-Cancel at the right. This
application puts commit-then-Cancel at the **leading** edge, in every dialog, in
a row that starts at the dialog's left margin rather than being right-aligned to
its footer. No dialog marks a default button, because with no keyboard nav there
is nothing for a default to mean.

### 4.3 An unwrapped explanation sets the dialog's width, and cites header files

> **Closed.** Two fixed widths, prose wrapped at them, Image Size 1766 → 920 px; the header citations are out of the dialog strings and the two engine strings that reached one (§0, S4).

`AlwaysAutoResize` widens a window to its widest unwrapped line, and these
explanations are `ImGui::TextDisabled()` with no wrap position set. So in six
of these dialogs **one sentence decides how wide the dialog is**:

| Dialog | Width | The unwrapped line that set it |
|---|---|---|
| Image Size | **1766 px** — 69% of the window | "Every layer resamples once, RGB, masks and any Pigment latents alike (**ops/DocumentTransform.hpp**); a Pigment layer's own kernel stays lobe-free regardless of this choice." |
| Emboss | **1648 px** | "0 amount is the identity. Distance 0 (or Depth 0) is a flat grey card, not a no-op — **ops/Filters.hpp section 7** says why a stylize filter's neutral point is not its identity." |
| Median | **1638 px** | "0 is the identity. Window is (2\*radius+1)^2 texels — radius 8 is a 17x17 window, the expensive end of this dial (**see this task's own [measured] median timing line**)." |
| Motion Blur | **1542 px** | "…an angle and angle+180 are the same request — **ops/Filters.hpp section 9** says so." |
| New Document | **1388 px** | "Reflects the clipboard as of the last time this window came to the front — copy, then click back into naturalPaint, before checking again." |
| Unsharp Mask | **1386 px** | "Threshold is shaper-domain (**ops/Filters.hpp section 2**): 0.02 ignores differences smaller than 27% of the local level, at every brightness." |

Look at [before/image-size.png](before/image-size.png): two fields and a combo occupying the
left third, then a wide band of empty dark grey, because of one line of prose.
[before/filter-emboss.png](before/filter-emboss.png) is the same shape with four sliders.

That prose also **cites source files at the user** — the bold spans above, plus
`core/Half.hpp` in the Export Comps warning and `ops/PointOpTiles` elsewhere.
Median's goes further and cites *a development task's own timing line*. These
are excellent engineering notes and they are being shown to a painter. The
distinction the codebase draws carefully everywhere else — between what a
comment says and what a user reads — is not drawn here.

**The fix already exists in this repository.** `ui/LabelledControl.hpp`'s
`textDisabledWrapped()` was written for precisely this failure ("the layers
panel's own status lines carry a document name and a counter triple, neither of
which is bounded, and an unwrapped one is cut off by the window"). It is used by
the docked column and by nothing in §2.

### 4.4 Three different commit models, undeclared

> **Closed.** The previewing dialogs say `Apply`; the live one says `Done` with a footer note that changes apply as they are made; the rest say the verb (§0, S2–S3).

- **Adjustments and filters**: preview live (or on release), then `Apply`/`Cancel`.
  Cancel discards the preview.
- **Image Size, Canvas Size, New Document, the Select five, Export**: no
  preview; the button acts.
- **Layer Properties**: *every edit applies immediately*, through the undo
  system, and the only button is `Close`. There is no Cancel and nothing to
  cancel.

All three look identical — same window chrome, same button row. A user has no
way to tell, before clicking, whether Cancel will undo what they just dragged.

### 4.5 Labels sit to the right of their controls — 33 of 34

> **Closed.** A right-aligned 116 pt label column in all thirty-five (§0, S5).

ImGui's default is a trailing label, and 33 of these dialogs take it:
`[ 0.000 ] Black in`, `[ 1024 ] Width`, `[ Catmull-Rom ▾ ] Resample`. Desktop
convention is a leading label — above the field, or right-aligned in a label
column to its left. With trailing labels there is no alignment column at all, so
the eye has to re-find the label after each control.

**Layer Properties is the exception**, and it is the exception because it uses
`ctlSlider()` / `ctlBeginCombo()` / `ctlInputText()` from `ui/LabelledControl` —
which draw a left label in a shared, measured column. Compare
[before/layer-properties.png](before/layer-properties.png) with
[before/adjust-levels.png](before/adjust-levels.png): the same widget vocabulary, two
different reading orders, one of them already correct.

### 4.6 Placement is inconsistent, and tall dialogs overflow

> **Closed.** All thirty-five exactly centred; the body scrolls under an 85% cap and the footer stays (§0, S7 -- including the first-frame trap that made the first attempt at this worse, not better).

ImGui centres a modal on first appearance with `ImGuiCond_FirstUseEver`
(imgui.cpp:13396) and then clamps it into the viewport. Twenty-six of the
thirty-four land exactly centred. Eight do not:

| Dialog | Size | Position | Centred would be |
|---|---|---|---|
| Revert | 362 × 266 | 1086, **42** | 1099, 657 |
| Export As | 1056 × 778 | 740, **42** | 752, 401 |
| Export Comps | 1200 × 1350 | 668, **42** | 680, 115 |
| Grow Selection | 508 × 350 | 1014, **42** | 1026, 615 |
| Feather Selection | 508 × 324 | 1014, **42** | 1026, 628 |
| Shrink Selection | 508 × 298 | 1026, **68** | 1026, 641 |
| Colour Range | 528 × 402 | 1004, **42** | 1016, 589 |
| Luminance Range | 588 × 402 | 974, **42** | 986, 589 |

`y = 42` is the top of the window content, under the menu bar. So a 266 px
dialog appears pinned to the ceiling while its 220 px neighbour appears centred,
for no reason a user can see. Separately, **Export Comps is 1350 px tall in a
1580 px window** (85%), which leaves the footer buttons a few pixels above the
status bar and gives the dialog nowhere to grow — see
[before/export-states.png](before/export-states.png).

### 4.7 Some dialogs open already showing an error

> **Closed.** Export Comps opens quiet with Export disabled and a hint; Revert on a never-saved document offers `Save As…` and no destructive button (§0, S8).

Two of the images above are red or amber on arrival, before the user has done
anything:

- [before/export-states.png](before/export-states.png) — `export refused: no output directory
  was given.` in red, on open, as the first-run state.
- [before/revert.png](before/revert.png) — the whole body is an amber engineering sentence
  beginning lowercase, `revert refused: 'Untitled' has never been saved…`, and
  the dialog still offers **`Discard and revert`**, an irreversible action that
  cannot succeed here because there is nothing to revert to.

Convention: an unmet precondition is a disabled control with a quiet hint, not a
refusal styled as a failure that already happened. A destructive button should
not be offered in a state where it has nothing to do.

### 4.8 Error and warning colours are hardcoded literals, off-palette

> **Closed.** `kError` / `kWarning` in the theme and `docs/ui.md`; zero literals left in `src/ui` (§0, S6).

`ImVec4(0.95f, 0.45f, 0.40f, 1.0f)` appears **17 times** in `ui/MacPaintUI.cpp`
and again in `ui/NewDocumentDialog.cpp`; the amber `ImVec4(0.92f, 0.78f, 0.35f,
1.0f)` twice more. `ui/AtelierTheme.hpp`'s token table — which `docs/ui.md`
mirrors row for row — has twelve roles and **no error or warning role at all**.
The red used is not `kAccent` (`#ff563c`) and not any other token; it is a
nineteenth colour that nothing governs.

### 4.9 Empty and degenerate states use the wrong words

> **Closed.** The empty Recover Documents dialog says `OK` (§0, S8).

[before/recover-documents.png](before/recover-documents.png) reads "No unfinished sessions
were found." and offers a button labelled **`Later`**. `Later` is the right word
for declining an offer; there is no offer. An empty state's dismiss button is
`OK` or `Close`.

### 4.10 One dialog is not a dialog

> **Closed.** Add Guide is a modal, and captured (§0, S9).

Add Guide (§3) is a `BeginPopup`, so it has no title bar, draws its own "Add
Guide" as body text, and dismisses on any click outside — a menu's behaviour, in
a place where every sibling is a modal. That inconsistency is also why it is the
one dialog this harness cannot photograph.

### What is already right

Worth stating, because a review that lists only faults invites regressions in
the parts that work:

- **Close document** is a correct destructive-choice dialog: three buttons, a
  40 px gap isolating `Don't Save` so a mis-aimed click on Cancel cannot land on
  it, `Don't Save` in the warning colour, Escape → Cancel and Return → Save
  through an asserted mapping, and **no key reachable to Don't Save**.
- **The modal scrim dims the chrome but deliberately not the canvas**
  (`ui/AtelierTheme.hpp`), so a live filter or adjustment preview stays legible
  underneath its dialog. That is a considered decision, not an oversight, and
  any restyling has to keep it.
- **Refusals name the layer and the reason** through one shared
  `pixelOpRefusalMessage()`, rather than each dialog inventing its own wording.
- **Every parameter dialog states its identity value** ("0 is the identity",
  "1.000 preserves this channel's level"), which is more than most reference
  applications do.

## 5. A proposed dialog standard

A concrete target to build against. Ordered so the earlier items are
independently shippable. **All nine are built** -- §0 has the per-item
disposition and the one place the implementation departed from the wording
below (S5's column is the dialog module's own constant, not `ui/LabelledControl`'s
measured one, for the reason given there).

**S1 — One dismissal contract.** Set `ImGuiConfigFlags_NavEnableKeyboard`, or
add a shared `dialogFooter()` that reads Escape and Return itself the way
`app/CloseDecision` already does. Escape cancels, Return commits, and the
commit button is drawn as the default. This closes §4.1 for all 34 at one call
site.

**S2 — One footer.** A single `dialogFooter(const char* commitLabel, bool
enabled)` helper: right-aligned to the dialog's trailing edge, `Cancel` then
commit, commit marked default. `drawAdjustmentButtons()` is already the shared
tail for thirteen of them — widen it rather than write a new one. Fixes §4.2's
placement and gives §4.4 somewhere to hang a per-dialog "this applies live"
note.

**S3 — Two commit labels, not nine.** `Apply` for anything that previews;
the verb for anything that does not (`Create`, `Export`, `Resize`, `Select`).
Never the dialog's own name.

**S4 — Wrap the prose and take the header paths out.** Route every
`TextDisabled()` explanation through `textDisabledWrapped()` at a fixed dialog
content width (480 px is enough for every control set here). Move the
`ops/…hpp` citations into the source comments they came from. Fixes §4.3, and
takes Image Size from 1766 px to roughly 560.

**S5 — Labels left, through the helper that already exists.** Convert the 33
trailing-label dialogs to `ui/LabelledControl`'s `ctl*` family. Layer Properties
is the worked example; the arithmetic is `app/ControlsLayout`'s and is already
tested.

**S6 — Two theme tokens.** Add `kWarning` and `kError` to
`ui/AtelierTheme.hpp`, add the two rows to `docs/ui.md`'s table, and replace the
19 literals. Fixes §4.8.

**S7 — Deliberate placement, and a height cap.** Centre every dialog explicitly
with `SetNextWindowPos(viewport->GetCenter(), ImGuiCond_Appearing, {0.5f,
0.5f})` rather than relying on `FirstUseEver` plus clamping, and give the two
export dialogs `SetNextWindowSizeConstraints` with a max height of ~80% of the
viewport so their content scrolls instead of the window overflowing. Fixes §4.6.

**S8 — Precondition states, not refusal states.** A dialog opening into an
unmet precondition disables its commit button and shows a quiet hint;
irreversible buttons are not offered when they cannot succeed. Revert with no
saved file should read "This document has never been saved" with `Save As…` and
`Cancel`. Fixes §4.7 and §4.9.

**S9 — Make Add Guide a modal**, like every one of its siblings — which also
makes it capturable, and closes the open question in §3 by removing the
mechanism that raised it.
